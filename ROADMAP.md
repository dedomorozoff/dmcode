# dmcode Roadmap — От прототипа к надежному TUI кодинг-агенту (в стиле crush)

Цель: быстрый, автономный, расширяемый локальный AI-ассистент для терминала на стеке **Go + adk-go + Bubble Tea**, способный читать, анализировать, точечно редактировать код, запускать тесты и сборку с контролем безопасности.

---

## Текущее состояние (v0.1.4)

- [x] Базовый агент на `google/adk-go` (`llmagent` + `openaimodel`).
- [x] Подключение через `.env` (Groq, OpenCode, OpenRouter, Mistral, GitHub Models, кастомные endpoint'ы).
- [x] Инструменты: `read_file`, `write_file`, `edit_file`, `list_dir`, `grep`, `glob`, `run_command`.
- [x] Базовый TUI на Bubble Tea: стриминг SSE, вывод вызовов инструментов, командная палитра (`Ctrl+P`), переключение моделей.
- [x] **Разметка Markdown в ответах:** заголовки, `**жирный**`/`*курсив*`/`` `код` ``, блоки кода с сохранением отступов, таблицы с выравненными колонками, цитаты `>`, разделители.
- [x] **Прокрутка колесом мыши:** включён `MouseMode`, события доходят до вьюпорта, скролл отпускает «липкий» низ; `/mouse` возвращает нативное выделение.
- [x] **Режимы Plan/Act по `Tab`:** PLAN оставляет только `read_file`, `list_dir`, `grep`, `glob`; `run_command` исключён, так как шелл пишет файлы.
- [x] **Рабочий каталог:** флаг `-C`/`--dir`, команда `/cd`, полный путь в сайдбаре.
- [x] **Границы рабочего каталога:** все пути проходят через `tools.resolve`; выход за пределы отклоняется с указанием обоих каталогов.
- [x] **Ещё бесплатные провайдеры:** Cerebras, NVIDIA NIM, SambaNova, Hugging Face — ключ без карты; GitHub Models и Mistral добавлены в мастер `/setup`.
- [x] **Строка состояния:** только режим и состояние. Имя модели убрано (третье место на экране), список хоткеев убран — он обрезался на узком терминале.
- [x] **`Tab` значит одно:** список `/`-команд выбирается стрелками и `enter`, поэтому `Tab` везде только режим.
- [x] **Диалог команд над вводом:** рамка в стиле `Ctrl+P`, рисуется поверх чата — кадр не сдвигается, сайдбар остаётся читаемым.
- [x] **Счётчик изменений в сайдбаре:** файлы и строки `+-`; считается диффом сессии, а не суммой вызовов.
- [x] **HTTP-прокси:** `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`, команда `/proxy` (показать, задать, отключить, исключения) с применением без перезапуска и записью в `.env`.
- [!] **Критические недоработки:**
  - Отсутствие отмены генерации / прерывания (Esc/Ctrl+C убивает весь процесс, а не ход).
  - Смена модели стирает сессию (`newSessionID`), хотя UI сообщает «контекст сохранён».
  - $O(N)$ перерисовка всей истории на каждый токен стриминга.
  - Проверка границ лексическая: симлинк внутри каталога всё ещё может выйти наружу.

## Фаза 1: Стабилизация ядра и исправление багов (Reliability & Stability) 🎯 В ПРИОРИТЕТЕ

> **Цель:** Сделать агента надежным, предсказуемым и безопасным в повседневной работе.

1. **Graceful Cancellation (Прерывание хода без выхода из TUI):**
   - Передавать `context.WithCancel` в `r.Run(...)` и выполнение команд.
   - По нажатию `Esc` или `Ctrl+C` во время генерации — прерывать текущий вызов LLM/инструмента и возвращать управление в поле ввода, сохраняя историю диалога.
2. **Исправление смены моделей и контекста:**
   - Сохранять текущий `sessionID` при пересоздании runner'а с новой моделью.
   - Миграция сессионного контекста в новый экземпляр `llmagent`.
3. **Кросс-платформенный шелл (`run_command`):**
   - Умное определение доступного интерпретатора (PowerShell 7 / Windows PowerShell / Git Bash / sh).
   - Поддержка трансляции путей Windows/Unix и корректных переменных окружения.
4. **Улучшение файловых инструментов:**
   - `edit_file`: нормализация `\r\n` $\leftrightarrow$ `\n`, поддержка контекстной замены с допуском пробелов (fuzzy whitespace).
   - `glob`: замена `filepath.Glob` на библиотеку с поддержкой `**` (например, `bmatcuk/doublestar/v4`).
   - `read_file`: возврат номеров строк для удобства LLM, безопасная обрезка без разрушения UTF-8.
   - Безопасная запись (`write_file`): атомарная запись во временный файл + rename, создание бэкапа перед заменой.
5. **Оптимизация рендеринга TUI:**
   - Кэширование отрендеренных строк истории (не форматировать всю историю заново при получении 1 токена).
   - Плавный скролл без фризов при больших логах.

## Фаза 2: Архитектурный рефакторинг (Modularization)

> **Цель:** Разделить монолит `main.go`, `tools.go`, `ui.go` на чистые пакеты.

- `internal/config`: загрузка конфигураций, профили провайдеров, хранение токенов.
- `internal/agent`: фабрика агента, системный промпт, настройки reasoning loop.
- `internal/tools`: регистрация инструментов, изоляция, проверка безопасности.
- `internal/ui`: компоненты Bubble Tea (viewport, status bar, command palette, picker, markdown view).
- `internal/session`: управление сессиями, сериализация.

---

## Фаза 3: UX, терминальный интерфейс и отображение изменений (Charm-grade TUI)

> **Цель:** Визуальный уровень и удобство charmbracelet/crush.

1. **Markdown & Code Syntax Highlighting:**
   - Интеграция `glamour` или подсветки синтаксиса `chroma` для блоков кода в ответах.
2. **Collapsible Tool Results (Интерактивные логи инструментов):**
   - Сворачивание и разворачивание длинного вывода (`[Enter]` на строке инструмента).
   - Показ статуса: выполнение (spinner) $\rightarrow$ успех (зелёная точка) / ошибка (красный крестик).
3. **Визуализация диффов (Diff View):**
   - Отображение правок `edit_file` в виде цветного git-diff (+/-) прямо в ленте сообщений.
4. **История ввода и автодополнение:**
   - Стрелки $\uparrow / \downarrow$ в поле ввода для навигации по предыдущим командам пользователя.
   - Улучшенное автодополнение путей к файлам по `Tab` (`@path/to/file`).

## Фаза 4: Безопасность и уровни разрешений (Permissions Engine)

> **Цель:** Контроль за деструктивными действиями агента.

1. **Режимы работы:**
   - `ask` (по умолчанию): запрос подтверждения в TUI (y/n) перед запуском шелл-команд и перезаписью файлов.
   - `auto-edit`: файлы правятся автоматически, команды шелла требуют подтверждения.
   - `yolo`: полный карт-бланш без подтверждений (для доверенных изолированных контейнеров).
2. **Блок-лист опасных паттернов:**
   - Запрет на команды вида `rm -rf /`, `mkfs`, `dd`, `git push --force` без явного подтверждения.
3. **Песочница путей (Workspace Jail):**
   - Запрет выхода за пределы рабочей директории проекта без предупреждения.

---

## Фаза 5: Долговечные сессии и контекст (Persistence & Memory)

> **Цель:** Сохранение сессий между перезапусками и эффективная работа с большими проектами.

1. **SQLite Persistence:**
   - Использование `session/database` из `adk-go` для сохранения диалогов в `~/.dmcode/sessions.db`.
   - Команды `/sessions`, `/resume <id>`, `/export <markdown>`.
2. **Context Compaction:**
   - Автоматическая суммаризация истории при приближении к лимиту контекстного окна модели (ADK `session/compaction`).
3. **Файловый контекст проекта (`.dmcode/rules` или `AGENTS.md`):**
   - Автоматическая загрузка правил проекта в системный промпт при старте.

---

## Фаза 6: Расширенная экосистема инструментов (MCP & LSP)

> **Цель:** Превратить dmcode в полноценную IDE среду для агента.

1. **LSP интеграция (Language Server Protocol):**
   - Подключение `gopls`, `pyright`, `tsserver` через LSP клиент.
   - Диагностика ошибок компиляции сразу после редактирования файла агентом.
   - Инструменты: `lsp_definition`, `lsp_references`, `lsp_diagnostics`.
2. **Поддержка MCP (Model Context Protocol):**
   - Клиент MCP (stdio / sse) через `adk-go` `mcptoolset`.
   - Подключение внешних инструментов из конфигурационного файла `dmcode.toml`.
   - Просмотр подключенных MCP-тулов через команду `/tools`.

---

## Фаза 7: Дистрибуция и релизы

- Конфигурационный файл `~/.dmcode/config.toml` (выбор модели по умолчанию, темы, хоткеи).
- Сборка кросс-платформенных бинарников через GoReleaser (Windows, Linux, macOS amd64/arm64).
- Автоматические тесты на GitHub Actions.
