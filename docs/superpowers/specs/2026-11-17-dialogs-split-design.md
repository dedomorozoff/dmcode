# C2 — вынести кластер оверлейных коробок из `ui.go` в `dialogs.go`

2026-11-17. Малая правка (короткий дизайн), подход уже показан пользователю и
одобрен («дальше»).

## Зачем

`internal/ui/ui.go` — ~6077 строк после C1; правка любого оверлея по-прежнему
конфликтует с любой другой. IMPROVEMENTS.md (C2) записал: кластер коробок
(~560 строк, теперь 580) по конвенции просит `dialogs.go`. Прецедент — C1
(`render.go`, `frame.go`): механический перенос, ноль изменений поведения.

## Что переносится

Один сплошной диапазон `ui.go` (с комментария перед `suggestBox` до конца
`langBox`): `suggestBox`, `floatingWidth`, `floatingPanel`, `floatingPanelAt`,
`floatingList`, `panelBox`, `panelWindow`, `paletteBox`, `modelPickerBox`,
`ggufPickBox`, `setupBox`, `langBox`. Ничего между ними нет — диапазон
непрерывен.

**Не переносится:** `proxyBox` (~строка 3420) — сидит посреди proxy-машины
(`proxyKey`/`proxyState`/`proxyFormRows`); рвать соседство не за чем.

## Как проверяется

Как C1: мультимножество строк (старый `ui.go` = новый `ui.go` + `dialogs.go`
минус два package/import-заголовка), `gofmt`, `go vet`, полный `go test ./...`,
сборка бинарника. Новых тестов не требуется — поведение не меняется, все
существующие тесты `internal/ui` остаются зелёными.

## Подходы

1. **Чистый перенос одного диапазона** (выбран) — единственный честный вариант
   для механики; проверяется мультимножеством.
2. Перенос с попутной реорганизацией (группировка, переименования) — отклонён:
   смешивать механику и правки нельзя, именно это C1 доказал не делать.
3. Выносить в пакет `internal/ui/dialogs` — отклонён: методы на `uiModel`
   тянут за собой экспорт половины состояния.

## Не-цели

- Не трогать диспатчер команд, клавиатурные обработчики, `proxyBox`.
- Не менять ни одной строки внутри переносимых функций.
